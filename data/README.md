# Data

## Source

The Abt-Buy benchmark from the Database Group of Prof. Erhard Rahm, Leipzig
University.

- Official page: https://dbs.uni-leipzig.de/research/projects/benchmark-datasets-for-entity-resolution
- Direct download used: https://dbs.uni-leipzig.de/files/datasets/Abt-Buy.zip
- Retrieved and verified: 2026-10-07
- Archive SHA-256: `b9ff2937d97371b7a00b0a97033213bfbdee24e8f1a0718a41ea8364472a8ff8`
  (134,745 bytes, contains 3 files)

Citation requested by the official page: the VLDB 2010 paper
*Köpcke et al., "Automatic Data Fusion with the Leipzig Benchmark Corpora"*
and the dataset page itself.

## License / usage wording (quoted from the official page)

> "January 2019: These datasets are made available by the database group of
> Prof. Erhard Rahm under the Creative Commons license. To give proper credit
> please refer to this website and the VLDB2010 paper [1]"

What is actually stated: the datasets are made available under "the Creative
Commons license". The page does **not** name a specific CC variant (no
CC-BY / CC-BY-SA / CC0 identifier), and it does not spell out whether
redistribution in a public repository is permitted. Because of that, the raw
CSVs are **not committed** here. `data/raw/` is gitignored and the setup step
below downloads them instead.

## Encoding

All three files are **not** UTF-8.

- `Abt.csv` fails UTF-8 decoding (11 non-ASCII bytes, e.g. `0xAE` = `®`,
  `0xB0` = `°`, `0xAD` = soft hyphen). It decodes cleanly as `cp1252`.
- `Buy.csv` and `abt_buy_perfectMapping.csv` are pure ASCII, so any encoding works.
- All three use CRLF line endings, no BOM, and quote every field.

The project therefore reads everything with `encoding="cp1252"`. Reading
`Abt.csv` as UTF-8 raises `UnicodeDecodeError`.

## Schema notes

- **Catalog A (`Abt.csv`) has no manufacturer column**, although the official
  page lists the task attributes as "name, description, manufacturer, price".
  Manufacturer is only available on the Buy side. This is a property of the
  benchmark, not a missing download.
- Prices are strings like `$399.00` and `$1,000.00`; many are empty.
  `$` and thousands separators must be stripped before numeric use.
- `Buy.csv` has 441 empty descriptions and 6 empty manufacturers.
- `Abt.csv` has 663 empty prices out of 1081.

The frozen split files live in `data/processed/splits/` (gitignored); run
`python -m entity_resolution.data` to regenerate them.

## Setup

```bash
mkdir -p data/raw
curl -L -o /tmp/Abt-Buy.zip https://dbs.uni-leipzig.de/files/datasets/Abt-Buy.zip
unzip -o /tmp/Abt-Buy.zip -d data/raw
```

Then check the checksums match the table above.

`data/processed/` is also gitignored; it holds the frozen split files and is
regenerated by the pipeline.

## Split files

`data/processed/splits/{train,val,test}_groups.csv` list the entity-group ids
assigned to each split. See `docs/methodology.md` for the method.
